🖥️ Melusina OS - The Operating System

Smart contracts handle the blockchain side, but running a regulated securities platform requires much more. That's where Melusina OS comes in.

This page provides a detailed look at the operational infrastructure that makes Sails.to work in practice.

What is Melusina OS?

A heavily modified version of Sandstorm.io integrated with Solana. It's like an "operating system" for regulated finance — providing all the tools brokers and issuers need to run their operations.

Pearls (Per-Issuance Containers)

Each investment Series gets its own isolated "pearl" — a containerized environment containing everything related to that specific offering:

What's in a Pearl

  • Series-specific parameters: soft cap, hard cap, duration, discount rate
  • Current phase status: Phase 1 (discount available) / Phase 2 (full price) / Closed
  • All legal documents: offering memo, project agreement, pledge docs, legal opinions
  • Token configuration: contract address, total supply, denomination rules
  • Investor registry: who subscribed, how much, at what price (discounted vs full)
  • Payment schedules: return payment dates, amounts, servicing state
  • Backups and audit trails: complete history, immutable records
Each pearl is like a separate filing cabinet for one project. Everything about "Series A" is in one cabinet, completely separate from "Series B". If something goes wrong with one, the others aren't affected.

Deployment Features

  • Their own users and permissions: Each organization manages their own team access
  • Their own compliance data: Never mixed with competitors — complete data isolation
  • Their own investor communications: Branded portals, custom notifications
  • Connected to the shared OTC network: Can trade with any other licensed broker
  • Access to the shared app store: Same apps, organization-specific configuration

Security Model

Melusina OS inherits Sandstorm's capability-based security model:

  • Grain isolation: Each pearl runs in its own sandbox
  • Capability tokens: Access is granted via unforgeable tokens, not ACLs
  • No ambient authority: Apps can only access what they're explicitly given
  • Audit logging: All actions are logged with cryptographic integrity

Why This Matters

In traditional systems, a bug in one part can compromise everything. With Melusina's capability model:

  • A compromised app can only affect the resources it was given access to
  • Cross-tenant data access is architecturally impossible, not just policy-forbidden
  • Audit trails are tamper-evident and anchored to the blockchain
