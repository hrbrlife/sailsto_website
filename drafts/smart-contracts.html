📜 Sails.to Smart Contracts

The Sails.to system runs on a suite of smart contracts deployed on Solana. These contracts enforce all the rules automatically — permissions, trading restrictions, fee distribution, and more.

This page provides a detailed reference for each contract in the system.

Governance & Permissions

🏛️ Platform Governance Contract

Purpose: The "master control" for the whole system

  • Controlled by a multisig (multiple people must approve changes)
  • Can pause the entire system in emergencies
  • Sets global parameters like fee rates
  • Approves upgrades to other contracts

📋 License Registry Contract

Purpose: The official list of who's allowed to do what

  • Stores all broker and issuer license status
  • Every other contract checks this before allowing actions
  • Query: "Is Broker X currently licensed?" → Yes/No

🎫 Broker License NFT Contract

Purpose: Issues and manages broker credentials

  • Mints non-transferable license NFTs
  • Enforces expiration dates
  • Allows revocation by platform
  • Supports renewal (update expiry, don't re-mint)

🎫 Issuer License NFT Contract

Purpose: Same as broker license, but for issuers

Identity & KYC

👤 Identity Registry & Wallet-Link Contract

Purpose: Connects legal identities to blockchain wallets

  • One identity can have multiple wallets
  • Supports adding/removing wallets
  • Handles key rotation (switching to new wallet)
  • Records which wallets are hot vs cold vs custodial

✅ KYC Credential Contract

Purpose: Proves an investor has been verified

  • Only licensed brokers/issuers can mint these
  • Contains: investor category, jurisdiction, expiry date, who verified them
  • Non-transferable (you can't sell your identity)
  • Revocable (if investor becomes ineligible or sanctioned)

Understanding the Credential System

Before anyone can do anything on Sails.to, they need the right "credentials" — special digital badges that prove they're allowed to participate. These are stored as non-transferable tokens (NFTs).

🎯 Think of it like: Security badges at a building. You can't give your badge to someone else, it expires and needs to be renewed, and security can revoke it if you break the rules.

Credential Who Gets It Who Issues It What It Allows
Broker License NFT Brokers Platform Execute trades, issue KYC credentials, access OTC network
Issuer License NFT Issuers Platform Create new investment series, manage investor communications
KYC Credential NFT Investors Brokers (or Issuers for known partners) Hold and trade security tokens

Why can't investors just use any wallet? The system separates identity from wallets. One investor can link multiple wallets to their identity (including cold storage like a Ledger). Security tokens can only be sent to wallets linked to a verified identity with a valid KYC credential.

Issuance & Securities

🏭 Series Factory Contract

Purpose: Creates new investment offerings

  • Only licensed issuers can use this
  • Creates a new "pearl" (isolated container) for each Series
  • Sets parameters: soft cap, hard cap, duration (default 4 mo), fees
  • Configures optional Phase 1 discount percentage
  • Deploys the associated token contract

🔒 Subscription Escrow Contract

Purpose: Holds investor money safely during fundraising

  • Receives subscription payments from all three channels
  • Tracks: who subscribed, how much, at what price, via which channel
  • Tracks current phase (Phase 1 vs Phase 2) based on soft cap status
  • Enforces duration limit (default 4 months)
  • Releases funds only when soft cap reached + conditions met
  • If soft cap fails: triggers zero-coupon redemption (returns invested capital minus minimal fees)
  • Triggers burning of unsold tokens at closing

📜 Security Token Contract

Purpose: The actual investment token

  • Minted upfront at offering start (amount = hard cap)
  • Transfer-restricted: checks recipient eligibility on every transfer
  • Enforces denomination rules (e.g., minimum €100,000 chunks)
  • Can be locked for custody/wrapping (Channel 3)
  • Supports burning unsold tokens at closing
  • Emits events for audit trails

Trading

💬 Quote/RFQ Registry Contract

Purpose: Where brokers post prices

  • Brokers publish indicative quotes (bid/ask/size)
  • Supports request-for-quote (RFQ) workflows
  • Only visible to other licensed brokers

🤝 Trade Execution Contract

Purpose: Actually executes trades

  • Verifies both parties are licensed and eligible
  • Calculates and distributes fees
  • Transfers tokens between broker wallets
  • Emits detailed audit events

📊 Broker Pool Registry Contract

Purpose: Tracks which brokers are active for which securities

  • Records broker liquidity commitments
  • Helps with routing and best execution

Fees & Finance

💰 Fee Splitter Contract

Purpose: Automatically divides fees to the right recipients

  • Issuance fees → Platform + Brokers + Admin
  • Trading fees → Broker + Platform
  • Conversion fees → Platform + Custodian
  • Deterministic, transparent, auditable

Conversion & Corporate Actions

🔄 Conversion Lockbox Contract

Purpose: Manages Solana ↔ Clearstream wrapping (powers Channel 3)

  • Receives and locks Solana tokens for wrapping
  • Enables issuer to wrap tokens for ISIN/Clearstream distribution
  • Emits conversion receipts for paying agent bank
  • Releases tokens only on validated redemption
  • Maintains strict 1:1 backing invariant
  • Tracks which tokens are wrapped vs unwrapped

📅 Corporate Actions Contract

Purpose: Handles ongoing payments and events

  • Schedules return payments (coupons, profit distributions, etc.) for Period 2
  • Processes principal repayments at maturity
  • Handles zero-coupon redemption if soft cap fails (returns invested capital)
  • Tracks discount prices to ensure correct redemption amounts
  • Handles redemptions and restructurings
  • Enforces record dates and blackout windows

📝 Audit Log Anchoring Contract

Purpose: Creates immutable proof of documents

  • Stores hashes of important documents (not the documents themselves)
  • Proves "this document existed at this time"
  • Used for: offering docs, agreements, notices, reports

Contract Interaction Summary

The contracts work together in layers:

  1. Governance layer controls who can participate
  2. Identity layer verifies eligibility for every action
  3. Issuance layer creates and manages securities
  4. Trading layer handles secondary market activity
  5. Finance layer manages money flow and corporate actions

Every transaction checks permissions through the governance contracts before executing.
